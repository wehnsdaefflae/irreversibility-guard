## Property-based search for UNDECLARED irreversible compositions

`python -m guard.search --depth 3 --json`, measured **2026-11-11**. **2940 action sequences** over 7 verbs × 2 locations, exhaustive to depth 3 and deterministic.

The oracle is a **concrete world model that does not import the guard**: locations really hold content, the acts really mutate them, and a violation is a sequence the guard allowed end to end that nevertheless left pre-existing content unreachable. Threat model: *the agent re-consents to its own HOLDs; only REQUIRE_HUMAN/DENY stop it*.

| configuration | hard-coded pair table (baseline) | derived effect-taint closure |
|---|---|---|
| **deployable** (undo path required, read-before-destroy on) | 184 violations | **0 violations** |
| composition isolated (those two gates off) | 2072 violations | 1022 violations |

In the deployable configuration the derived mechanism catches **184** sequences the pair table misses, of which **184** correspond to no entry in that table at all — irreversible compositions nobody declared. Two were checked into the scenario table above as `bp-10` and `bp-11`; `bp-11` (a copy onto an occupied path, declared reversible) is a hazard the search found and the author had not thought of.

**Read the second row carefully.** With the two ordinary gates off, the derived closure reports MORE violations than it does deployed, and in that configuration the pair table reports more still. That is a property of what each mechanism is for: the closure deliberately defers a *bare* destructive act to the gate that owns it (read-before-destroy, undo path) because that gate gives a clearer reason code, so with those gates removed nothing catches those acts. Only the first row describes a guard anyone would deploy. Both are printed because quoting the first alone would overstate the mechanism.

Full findings, including the search alphabet and worked examples: `tests/search-findings.json`.
