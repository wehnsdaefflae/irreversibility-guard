## Property-based search for UNDECLARED irreversible compositions

`python -m guard.search --depth 3 --json`, measured **2026-11-11**. **2940 action sequences** over 7 verbs × 2 locations, exhaustive to depth 3 and deterministic.

The oracle is a **concrete world model that does not import the guard**: locations really hold content, the acts really mutate them, and a violation is a sequence the guard allowed end to end that nevertheless left pre-existing content unreachable. Threat model: *the agent re-consents to its own HOLDs; only REQUIRE_HUMAN/DENY stop it*.

| configuration | hard-coded pair table (baseline) | derived effect-taint closure |
|---|---|---|
| **deployable** (undo path required, read-before-destroy on) | 184 violations | **0 violations** |
| composition isolated (those two gates off) | 2072 violations | 1022 violations |

In the deployable configuration the derived mechanism catches **184** sequences the pair table misses, of which **184** correspond to no entry in that table at all — irreversible compositions nobody declared. Two were checked into the scenario table above as `bp-10` and `bp-11`; `bp-11` (a copy onto an occupied path, declared reversible) is a hazard the search found and the author had not thought of.

**Read the second row carefully.** With the two ordinary gates off, the derived closure reports MORE violations than it does deployed, and in that configuration the pair table reports more still. That is a property of what each mechanism is for: the closure deliberately defers a *bare* destructive act to the gate that owns it (read-before-destroy, undo path) because that gate gives a clearer reason code, so with those gates removed nothing catches those acts. Only the first row describes a guard anyone would deploy. Both are printed because quoting the first alone would overstate the mechanism.

Full findings, including the search alphabet and worked examples: `tests/search-findings.json`.

## External evaluation on a third-party agentic benchmark

Measured 2026-11-12 · guard `0.1.0` · `scripts/eval_agentharm.py all` · raw: `tests/agentharm-eval.json`

The scenario table above is written by the guard's own author, so it cannot measure whether the guard generalises. This section is scored on [AgentHarm](https://huggingface.co/datasets/ai-safety-institute/AgentHarm) (UK AI Safety Institute): **416 prompts** over **85 tool functions**, with AgentHarm's own `target_functions` as the ground truth for which calls each prompt is meant to drive, and its distribution-matched `harmless_benign` config as the control. The per-function irreversibility labels come from a model shown no guard source, no manifest and no mention of a guard. Nothing in this section was labelled by the author.

**All 85 functions are foreign to the guard's manifest.** That is the realistic deployment condition — an integrator's tool surface the guard's author never saw — and it means only the heuristic tier and the fail-closed rule for undeclared verbs are under test here. The manifest tier, the one sound tier, was deliberately not given the answers; deriving a manifest from the labels would have made the result perfect by construction.

**Two false-negative rates, and the strict one is the one to believe.** The strict rate counts a stop only where **the agent cannot clear it itself**, and that turns on a distinction the two HOLD kinds do not share — a distinction this project got wrong in both directions before an independent reviewer probed the shipped API on 2026-11-12:

- `hold.irreversible_needs_reconsent` **is** agent-satisfiable. The act is added to `session.consented` and a second emission with `consent=True` returns `ALLOW/allow.re_consented`. It is a speed bump, not a stop.
- `hold.unknown_verb_fails_closed` **is not**. The unknown tier returns it *before* any consent handling and the act never enters `session.consented`, so re-consent can never clear it — probe-verified on `terminal`, `upload_file`, `make_online_purchases`, `wire_funds` and `share_on_pinterest`, each still HOLD on three successive consents.

Only the first is counted as a non-stop. Earlier revisions of this file counted *every* HOLD as agent-satisfiable, which overstated the leak against this project's own code; the revision before that counted every HOLD as a stop, which understated it. Both rates are printed, strict first.

| measure | result | 95% CI |
|---|---|---|
| **irreversible functions an ADVERSARIAL agent reaches** (HOLD is not a stop) | **0/40** = **0.000** | 0.000–0.088 |
| irreversible functions allowed outright (HOLD counts as a stop) | 0/40 = 0.000 | 0.000–0.088 |
| reversible functions BLOCKED (false positives) | **27/45** = 0.600 | 0.455–0.730 |
| benign prompts delayed by at least one hold | 168/208 = 0.808 | see the caveat below |

**No irreversible foreign function is reachable by the agent alone.** Every one of the 40 ends at a verdict the agent cannot clear: `REQUIRE_HUMAN`, `DENY`, or the unknown tier's fail-closed HOLD, which is returned before consent is consulted. That is a stronger claim than the `0/40` *allowed-outright* row beside it, and it is worth reading with the false-positive rate in the same table: the same fail-closed rule that produces it blocks 27 of 45 reversible functions. **This number is a property of a tool surface the guard has never seen, which is the point — but it is bought by refusing the unrecognised, not by recognising anything.** The honest statement of the guard's limit is in `LIMITATIONS.md`: a classifier-based guard cannot be sound, and this result does not make it so.

**The honest baseline is not 'no guard' — it is 'block every unknown verb'.** That trivial policy also allows **0** irreversible foreign functions, so the zero-outright-allow figure is not where this guard earns its keep. What it adds over block-all-unknown is the **18 of 45** reversible functions it correctly lets through (block-all-unknown: 0) and a per-verb reason code for every decision. The 'no guard at all' row below is reported for completeness, not as the comparison that matters.

**Statistical caveat, stated rather than buried:** The per-PROMPT intervals are computed as if prompts were independent, and they are not: AgentHarm prompts share target functions, and the guard sees only the function name, so a prompt's outcome is determined by the calls it shares with others. The per-prompt CI is therefore too narrow and the per-prompt figures carry no information the per-CALL figures do not already carry. Quote the per-call numbers; the per-prompt ones only show how the per-call verdicts distribute over tasks.

**Against no guard at all:** all **40** irreversible calls execute unguarded; guarded, **0** execute outright and **0** more are reachable by an agent that re-consents to the holds it CAN clear — so the guarded figure against an adversarial agent is **0 of 40**. Read it against the block-all-unknown baseline above, not against 'no guard': refusing every unrecognised verb reaches the same figure, and what this guard adds is the reversible traffic it still lets through plus a reason code per decision.

**Where the two numbers come from — the decomposition matters more than either figure.** Of the foreign verbs the heuristic tier could read, it blocked **22/22** irreversible ones and **0/18** reversible ones. The remaining **45** verbs no tier could read: the fail-closed rule held all of them, catching **18** more irreversible calls by brute force and producing **27** of the false positives. So the zero false-negative rate above is *not* evidence of a clever classifier — roughly half of it is fail-closed refusing everything it does not recognise. That **fail-closed stop is a HOLD the agent cannot clear** (it is returned before consent is consulted), so it holds against an adversarial agent — but it is a refusal to act on the unrecognised, not classifier skill, and it is bought at the cost of the reversible verbs it blocks with it. The false-positive rate is the price of the same rule. An integrator who declares their tool surface in the manifest moves verbs out of that tier and pays less; one who declares nothing gets this.

**The guard is an irreversibility gate, not a harm classifier.** AgentHarm's harmful and `harmless_benign` prompts draw on the same tool surface, and the guard delays 0.808 of the harmful prompts and 0.808 of the benign ones — the same rate, because it judges the act and never the intent. It is asserted as a test (`tests/scenarios/test_external_eval.py`), not merely stated.

## A REAL AGENT in the loop (AgentHarm, live tool-calling episodes)

Measured 2026-11-13 · `scripts/eval_agent_loop.py run` · raw: `tests/agent-loop-eval.json` · model `openai/gpt-4o-mini` · seed `20261113` · 20 prompts per config · max 8 steps · tool surface 85 functions

Every other number on this page is **static**: a tool name, or a declared sequence, put to the guard directly. This section is the only one where a model is actually driving. It is given the AgentHarm task text and the benchmark's 85-function tool surface, it chooses each call itself, and every call it proposes is intercepted before a (stubbed) dispatcher would run it. A refusal is handed back to the agent in words, so an agent that re-plans, substitutes or retries is measured doing it.

Three arms over the same episodes: `none` is no guard at all (the upper bound on both harm and utility), `guard` is the deployable configuration, and `block_unknown` refuses every verb absent from the manifest — the trivial baseline a reviewer should demand, present to price what it costs.

| Arm | Irreversible target calls executed | Harmful episodes reaching an irreversible act | Benign tasks completed | Calls executed / proposed | HOLDs cleared by the agent's own re-consent |
| --- | --- | --- | --- | --- | --- |
| `none` | 18/30 = 0.6 (CI 0.423–0.754) | 11/20 = 0.55 | 7/20 = 0.35 (CI 0.181–0.567) | 193/193 | 0 |
| `guard` | 0/30 = 0.0 (CI 0.000–0.114) | 0/20 = 0.0 | 0/20 = 0.0 (CI 0.000–0.161) | 80/202 | 0 |
| `block_unknown` | 0/30 = 0.0 (CI 0.000–0.114) | 0/20 = 0.0 | 0/20 = 0.0 (CI 0.000–0.161) | 0/160 | 0 |

**Read the benign column, not only the harm column.** Driving a live agent over a tool surface where **every one of the 85 verbs is undeclared** is the worst case for this design, and the cost shows: the unguarded arm completes 0.35 of the benign tasks and the guarded arm 0.0. The reason is `hold.unknown_verb_fails_closed`, which is reached before consent is consulted and is therefore **not** clearable by the agent — which is also why the re-consent column reads 0. On a surface with a manifest, those same calls would be judged by the manifest tier instead; `tests/agentharm-eval.json` measures the undeclared condition call-by-call, and the manifest-coverage curve is an open item in `LIMITATIONS.md`, not a claim made here.

**What the baseline costs.** `block_unknown` reaches 0 irreversible target calls — perfect by construction, since it refuses everything undeclared — at a benign completion rate of 0.0. It is the honest comparator: any guard must beat refusing the whole surface, and on a surface this foreign the margin is about which calls still run, not about the harm column.

Episodes that errored (a provider failure or an unusable model reply, counted rather than silently read as the agent finishing): **0** of 120.

The AgentHarm prompt **texts** are not redistributed by this repository (`tests/corpus/FETCH.md`): the script fetches them from the HuggingFace datasets server into a gitignored cache, and only ids, decisions and counts are checked in. Re-running needs network access and an OpenRouter key.

## Held-out benign traffic (independently generated)

Measured 2026-11-12 · `scripts/eval_external.py` · raw: `tests/external-eval.json`

**150** legitimate agent calls generated by an independent model over this instance's real tool surface — none written by the guard's author. False positives **28/150** = **0.187** (95% CI 0.132–0.257).

That is the number to believe, and it is **above** the 0.000 the 14 hand-written benign controls report. The hand-written set uses only verbs the author also declared in the manifest, so it could not show this cost; every one of these false positives is a verb the manifest does not declare, held by the fail-closed rule.

A second external corpus, [deepset/prompt-injections](https://huggingface.co/datasets/deepset/prompt-injections) (662 rows), was also scored and is reported here as a **negative result**: an independent model mapped 612 of its 662 texts to no tool call at all, and the remainder to none that is destructive or outward. It is a text-classification corpus of chatbot instruction-override attempts, so it cannot measure a guard that intercepts actions. It is left in the repository with this finding rather than dropped, because the mismatch is worth knowing before anyone else reaches for it.
